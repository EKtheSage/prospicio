### Reserving

- An a-priori loss ratio per origin on `ExpectedLoss`, `BornhuetterFerguson` and `Benktander` (`Apriori`, `reserving-v02.md` decision 20): one number for every origin, one per origin oldest first (`Apriori::InOrder`), or one per origin period (`Apriori::by_origin`, `Apriori::from_labels` with labels such as `"2021"` or `"2021Q3"`). It is keyed by origin, since a latest diagonal's fit sorts its origins and a triangle segment is trimmed to the origins it observes; an origin without a value, a value for an origin the triangle does not have, an origin given twice or the wrong number of values in order is an error (`Error::Apriori`). It reaches segment fits (each segment takes its own origins' values), `fit_diagonal` and its segment versions, and the one-year re-reserving method of both bootstraps. Python `apriori` takes a float, a sequence in origin order or a dict keyed by origin label or year, and the property gives it back as given; R `apriori` takes a number, a vector in origin order or a vector named by origin. `CapeCod` is unchanged (#634, #641).
- **Breaking:** the `apriori` field of `ExpectedLoss`, `BornhuetterFerguson` and `Benktander` is an `Apriori`, not an `f64`: write `apriori: 0.7.into()`. `Error` has a new variant, `Error::Apriori` (#641).
